## 0. 기본 원칙
- 사용하지 않는 코드나 에셋은 즉시 삭제하라.
- **금지:** `global` 변수 사용, 하드코딩된 좌표 값
- 내부 동작의 기본 언어(코드, 식별자, 주석 의도)는 영어로 할 것
- 사용자 대상 응답 및 문서(readme, history)는 한글로 작성할 것

## 1. 개요
- **목적:** HTML5 기반의 웹 메모장 앱
- **엔진/언어:** TypeScript
- **핵심 목표:** 폐쇄망 동작 가능한 단일 산출물 웹앱

## 2. 작업 규칙
- 모든 변경은 **설계 → 테스트 작성 → 구현 → 검증** 순서로 진행
- 한 번에 하나의 이슈만 해결하고, 테스트 통과 확인 후 `git commit`, 그다음 아이템으로 진행
- 작업 완료 후 `history.html`에 한글로 이력 기록 (최신 항목을 첫 `<h2>` 위에 추가)
- `readme.md`는 한글로 유지
- 관리 에이전트가 개발·검증·디자인 에이전트를 관리
- 에이전트 간 통신은 영어로 한다
- 작업 완료 후 GitHub에 푸시

## 3. 실행/빌드 제약
- 실행 시 외부 라이브러리 참조가 있으면 안 됨 (CDN, 외부 폰트 포함 금지)
- HTML5 표준 기반으로 구현
- `python -m http.server 8001` 로 동작 가능해야 함
- 브라우저 기본 지원 폰트만 사용

## 4. 이미지·사운드 리소스
- 이모지를 최대한 활용
- 인터넷 무료 이미지 리소스 사용 시 출처 표기
- 인터넷 무료 오디오 리소스 사용 시 출처 표기
- 오디오 리소스는 base64로 변환하여 JS에 포함시킬 것

## 5. 코딩 규칙 (Coding Rules)
- 모든 코드는 모듈화하여 작성
- 변수·함수명은 `camelCase`, 클래스명은 `PascalCase` 사용
- 주석은 코드의 의도를 명확히 설명할 것
- 성능에 미치는 영향을 고려하여 최적화된 코드를 작성
- 코드를 수정하기 전에 `test` 폴더의 기존 로직을 확인하라

## 6. 저장 메커니즘 (DB & Store)
- **DB:** 브라우저 IndexedDB 사용
- 데이터는 JSON 형식으로 저장·불러오기 가능
- 내부 DB를 통해 여러 작업물을 저장 및 불러오기 가능
- 구조상 필요하다면 모든 DB 내용을 하나의 JSON으로 다운로드 및 등록(가져오기) 가능
- 구조상 필요하다면 내부 DB에 저장된 작업물의 삭제·이름 변경·불러오기 가능
- 사용자의 진행 상황은 IndexedDB에 저장되어 **작업 이어하기** 지원
- 데이터 형식(JSON)은 수정과 추가가 쉬워야 함
- DB 손상·오류 상황에서도 앱이 동작해야 함

## 7. 지원 환경 (Targets)
- PC 브라우저 동작 가능
- 모바일 터치 UI 지원
- 폴더블 기기의 펼침 화면·접힘 화면 모두 지원
- 갤럭시 폴드8 펼침 화면에서 고해상도로 보이도록 할 것

## 8. 기능 목표 (Goals)
- 한글·영어 다국어 지원
- 브라우저가 지원하는 기본 폰트만 사용
- Mirror6 사용 및 소스에 포함 (폐쇄망 사용)
- 탭 지원 (동시 여러파일 불러오기)
- 로컬 파일 불러오기 및 저장 지원

## 9. 마무리 (Build & Release)
- 빌드 시 `index.html` 하나의 산출물로 나오도록 할 것
- `index.html`만 `release` 폴더로 복사하는 `build.sh`(POSIX) 작성
- `index.html`만 `release` 폴더로 복사하는 Windows용 `build.bat` 작성
- Windows용 `build.bat`는 한글이 깨지지 않도록 cp949 사용
- 인터넷 검색하여 좋은 아이디어가 있으면 추가할 것

## 10. 로드맵 (Roadmap)
- 항목 하나 = 커밋 하나. 실패하는 검사를 먼저 작성하고, 끝난 항목은 `[x]`로 표시
- 각 Phase 끝의 마일스톤(M0~M6)에서 `test/manual/checklist.md`로 브라우저 확인
- 화면은 자동 검증 수단이 없으므로 PC / 폴드 접힘 / 폴드 펼침에서 직접 확인

### 확정된 결정
- 폐쇄망 범위: **실행만** 폐쇄망. 빌드는 npm(esbuild·tsc·CodeMirror 6, `package-lock.json` 고정)
- 에디터: CodeMirror 6 (8절의 "Mirror6"). `@codemirror/state`·`view`·`commands`·`search`만 번들
- 타입 검사는 TypeScript 6.x (7.x는 Android용 바이너리 없음), 테스트는 Node 내장 `node:test`
- CP949/Johab 파일은 UTF-8로 저장하고 안내. 줄바꿈(CRLF/LF)과 BOM은 원본 유지
- 대상 브라우저: PC Chrome/Edge, 폴드의 Chrome·삼성 인터넷. iOS는 되는 만큼만
- 접속 주소는 `http://localhost:8001` (`127.0.0.1`은 다른 출처라 DB가 분리됨)
- `release/index.html`은 마일스톤 완료 때만 커밋

## 11. ssMemoWeb에서 가져온 아이디어
- **그대로 가져옴**
  - 종료 시 전체 저장(`pagehide`/`visibilitychange`) + 미저장일 때만 이탈 경고
  - 대용량 로딩 절차: 10MB 제한, 200KB 이상 로딩 표시, 단계 사이 양보, `finally` 정리
  - `encoding.js`, `markdown.js`, `calc.js`, `file-utils.js` (TypeScript로 이식)
  - 파비콘 base64 내장, 산출물 검증 테스트
- **고쳐서 가져옴**
  - 저장소 추상화 + 메모리 폴백 → 상시 상태 배지, 임시 모드에서도 백업 가능
  - Promise 모달 → `<dialog>` 하나로 통일, ESC는 맨 위 창만 닫음
  - 탭 → "메인 탭" 특례 없이 모든 탭 동일, 메모와 파일을 한 종류의 문서로
  - 단축키 → 표 하나에서 키맵과 도움말을 함께 생성
  - cp949 `build.bat` → 단계 실패 시 중단
- **고치는 약점**
  - 제목이 DB 키라 이름 변경이 비원자적 → 고정 id
  - 저장 성공을 트랜잭션 완료 전에 보고 → `tx.oncomplete` 기준
  - 한글 문자열 약 160곳 하드코딩 → 다국어 카탈로그
  - 이어하기가 메모 1개만 복원 → 열린 탭·커서까지
  - 터치 영역 32px, 폴더블 미대응 → 44px 이상, safe-area·`dvh` 적용
  - 프로그램적 편집이 실행 취소를 지움 → CM6 트랜잭션
  - `markdown.js`가 CRLF에서 깨짐, `calc.js`가 `constructor`를 계산함 → 이식 시 수정
- **가져오지 않음**
  - 줄번호·검색·줄바꿈 자체 구현 (CM6가 대체)
  - `RestSource`, 수동 모듈 순서 번들러
  - 평문 비밀번호가 든 `upload.sh` 방식
